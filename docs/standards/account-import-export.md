# 账户导入导出规范

- 状态：第一阶段必须实现
- 日期：2026-09-16

## 1. 目标

统一 Web、Android 和 iOS 的批量文件语义，避免三端各自解释字段、覆盖规则或“导出全部”。服务端是校验和结果的唯一事实源，客户端只负责选择文件、显示预检结果和下载/分享结果。

## 2. 文件格式

- 导入只接受官方 `.xlsx` 模板，不接受自由列名的 Excel、CSV 或旧版 `.xls`。
- 模板版本写入隐藏元数据和文件名，例如 `shtong-account-import-v1.xlsx`。
- 最大 5,000 个账户、10 MB；超过限制拆分文件。
- 单元格按文本读取，禁止公式、宏、外部链接、隐藏业务数据和嵌入对象。
- 所有业务代码保留前导零，不把学号、组织代码或人员编号转为数值。

模板包含三个工作表：

### 2.1 `accounts`

| 列 | 必填 | 规则 |
| --- | :---: | --- |
| `row_key` | 是 | 文件内唯一关联键，不写入业务主键 |
| `login_name` | 是 | 全局唯一，规范化后仍须唯一 |
| `display_name` | 是 | 1 至 100 字符 |
| `person_no` | 是 | 学工号等稳定业务编号，全局唯一 |
| `class_code` | 条件 | 角色包含 `USER` 时必填；组织树中必须存在且有效 |

### 2.2 `role_assignments`

| 列 | 必填 | 规则 |
| --- | :---: | --- |
| `row_key` | 是 | 引用 `accounts.row_key` |
| `role_code` | 是 | `USER`、`TEACHER_ADMIN`、`STUDENT_ADMIN`；禁止批量导入 `SYSTEM_ADMIN` |

同一 `row_key + role_code` 不得重复。一个账户可有多行不同角色。

### 2.3 `assignment_scopes`

| 列 | 必填 | 规则 |
| --- | :---: | --- |
| `row_key` | 是 | 引用 `accounts.row_key` |
| `role_code` | 是 | 必须引用该账户已有的管理员角色行 |
| `org_unit_code` | 是 | 引用已存在且有效的组织节点业务代码 |

- `TEACHER_ADMIN` 只能引用 `GRADE`，并至少有一行。
- `STUDENT_ADMIN` 可引用 `COLLEGE`、`GRADE`、`CLASS` 任意组合，并至少有一行。
- `USER` 使用 `SELF`，不允许出现在此表。

## 3. 导入流程

```text
下载模板
-> 客户端本地做文件类型/大小提示
-> 上传并创建校验任务
-> 服务端病毒扫描、模板版本识别、规范化和全量校验
-> 返回汇总与逐行错误，不写业务数据
-> 系统管理员确认并提交（reason + idempotency key）
-> 单事务写入账户、凭据、角色、管辖上限、审计和 outbox
-> 返回一次性临时密码结果文件
```

- 首期导入只创建新账户，不更新、合并或覆盖已有账户。
- 文件中任一行错误时禁止提交，避免半成功后难以追踪。
- 校验通过只代表当时可提交；确认提交时必须重新检查唯一性、组织 revision、操作者会话和权限。
- 校验任务默认 24 小时过期，过期或组织 revision 改变后必须重新校验。
- 原始导入文件按受控临时对象处理，记录 SHA-256、模板版本、行数和提交者；到期删除原文件，不进入普通日志或审计 payload。
- 审计 manifest 保存实际创建账户集合及必要的非秘密字段摘要。

## 4. 临时密码结果

- 导入模板不包含密码列，服务端为每个账户生成独立随机临时密码。
- 结果文件只包含 `login_name`、`display_name` 和一次性初始密码；初始密码不设置有效期。
- 文件使用服务端加密，只允许同一发起系统管理员下载一次，下载后立即清除。
- 下载地址短期有效且最多成功下载一次；下载行为单独审计。
- 服务端不提供“再次查看密码”，文件过期或丢失后只能执行密码重置。

## 5. 导出集合规则

导出请求必须显式使用一种模式：

```text
SELECTED: account_ids 非空，只导出这些不可复用内部 ID
FILTERED_ALL: account_ids 不出现，导出 filter 在提交时命中的全部账户
```

- UI 有任何已选账户时使用 `SELECTED`。
- UI 没有已选账户时使用 `FILTERED_ALL`，并显示“将导出当前筛选结果 N 条”；没有筛选即为所有可见、非逻辑删除账户。
- 服务端不从空数组猜测模式；`SELECTED` 的空数组和缺少 `filter` 的非法请求均拒绝。
- 查询条件、排序不影响集合、授权版本、组织 revision、预计数量和用途说明随任务冻结。
- 文件生成前再次验证当前会话和权限；权限已撤销时任务失败，不生成可下载文件。

## 6. 导出字段

首期账户导出允许：

- 账户内部 ID、登录名、显示名称、人员编号。
- 学生可空性别；非学生账户导出为空。
- 生命周期状态、安全锁定状态、密码是否需要修改。
- 当前班级及推导出的学院、年级业务代码和名称。
- 角色代码、角色有效期、教师/学生管理员直接管辖上限。
- 创建时间、更新时间、最后成功登录时间。

禁止导出：

- 当前或历史密码、密码哈希、salt、临时密码。
- refresh/access token、Cookie、MFA secret、恢复码、设备私钥。
- 审计内部完整性密钥、KMS 信息或未授权敏感字段。

导出时间使用 ISO 8601，另附数据字典工作表。文件包含任务 ID、生成时间、发起人、用途和“内部受控数据”水印。

## 7. 文件生命周期

- 导出与临时密码文件存入私有对象存储，不经应用实例长期落盘。
- 普通账户导出默认 24 小时到期；临时密码结果最长 24 小时且只允许一次下载。
- 下载使用短期票据，签发和实际下载分别审计。
- 到期清理不删除导出任务、manifest、文件 hash 和审计证据。
- 文件生成失败、审计提交失败或权限复核失败时不得进入 `READY` 状态。

## 8. 移动端交互

- Android 使用系统 Storage Access Framework 选择导入文件和保存/分享导出文件。
- iOS 使用 Document Picker 选择导入文件，以系统 Share Sheet 或 Files 导出结果。
- 移动端不得把账户导出或临时密码文件静默保存到公共相册、普通缓存或可备份偏好目录。
- 文件预检、提交确认、任务进度和错误报告与 Web 使用同一 API 和错误代码。

## 9. 审计事件

- `ACCOUNT.IMPORT_VALIDATION.REQUESTED`、`ACCOUNT.IMPORT_VALIDATION.SUCCEEDED`、`ACCOUNT.IMPORT_VALIDATION.FAILED`
- `ACCOUNT.IMPORT.COMMITTED`、`ACCOUNT.IMPORT.COMMIT_FAILED`
- `ACCOUNT.IMPORT_RESULT.DOWNLOADED`
- `ACCOUNT.EXPORT.REQUESTED`、`ACCOUNT.EXPORT.COMPLETED`、`ACCOUNT.EXPORT.FAILED`、`ACCOUNT.EXPORT.DOWNLOADED`

每个事件包含文件/任务 ID、文件 hash、模板版本、记录数量、结果、原因、操作者和目标 manifest 引用，但不包含原文件正文或临时密码。

## 10. 验收重点

- 重复登录名、重复人员编号、未知班级、角色缺 scope、错误节点类型和模板篡改均在预检阶段报告。
- 校验通过后组织 revision 改变，提交必须要求重新校验。
- 无选择导出精确等于当时筛选结果，不受后续翻页或修改筛选影响。
- 跨页选择导出不丢失 ID，也不混入未选择账户。
- 无权限账号即使构造请求也不能创建、查询或下载任务。
- 临时密码不出现在审计、日志、异常栈或普通账户导出中。
# 中文默认模板补充（2026-09-16）

依据管理员易用性需求，默认下载模板为 `v3-zh`，接口及既有导入审计事件编号保持不变。`账户名单` 一人一行，表头固定为：登录账号、姓名、学工号、性别、所属班级、身份、管理范围。性别选填且只供普通用户身份填写，可选男、女、其他；姓名允许重名，学工号仍唯一且创建后不可修改。显示名称和模板表头唯一来源为 `packages/contracts/presentation/account-access.zh-CN.json`。

身份填写普通用户、教师/辅导员、学生管理员。所属班级和管理范围接受有效组织编号、完整路径名称或唯一短名称；重名必须用完整路径或编号。多个管理范围用中文分号、英文分号或换行隔开。普通用户必须有班级，教师范围只能为年级，学生管理员范围可以是学院、年级或班级。每行填写一个初始身份，多身份通过账户授权补充。

模板附带只供查阅的“填写说明”和动态“组织对照”，示例不混入账户数据。账号和学工号按文本填写以保留前导零。禁止隐藏数据、公式和外部链接；错误定位至工作表、行和中文列名。空文件和更改表头均不通过预检。

`v3-zh` 版本标记写入工作簿自定义属性 `templateVersion`，不使用隐藏工作表存放数据；中文文件名不要求管理员理解版本号。此条替代旧版“隐藏元数据/文件名”展示约定，不改变拒绝隐藏账户数据的安全要求。

原 `v1` 三表英文模板和 `v2-zh` 六列中文模板仍兼容，不删除历史协议；旧模板导入的性别为空。账户导出、密码发放文件和操作记录导出使用中文表头及状态名称，继续执行原有权限、审计、CSV 注入防护及一次性下载规则。
