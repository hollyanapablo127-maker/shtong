# ADR-0003：服务端权威的不可变审计账本

- 状态：已接受
- 日期：2026-09-15
- 当前实现说明：登录已改为仅账号密码，MFA/step-up 已移除；本文涉及 MFA/step-up 的内容为长期设计，不代表当前行为，见 [ADR-0005](0005-password-only-login-and-incremental-persistence.md)。

## 背景

系统要求所有涉及用户、账户、授权、组织字段、业务、审批、统计和审计本身的操作都可追踪。普通应用日志和客户端埋点无法提供完整、可靠且防篡改的证据。

## 决策

- 所有受保护 API、认证与授权决策、业务用例、后台任务、读取、查询、导出和审计访问均产生服务端权威审计事件。
- 客户端页面和按钮事件作为单独的产品遥测，不能替代审计。
- 业务写入、审计事件、涉及主体/资源/字段差异和 outbox 在同一 PostgreSQL 本地事务提交。
- 读取在释放受保护数据前持久化实际返回主体的审计关联。
- 受保护操作在权威审计无法持久化时关闭失败；worker 只复制、建查询投影和归档，不能首次创建权威事件。
- 账本只追加；修正通过新事件引用原事件，运行时角色无 UPDATE/DELETE 权限。
- 小集合关系直接进入完整规范化 envelope；大集合使用事务内不可变加密 manifest，异步展开行只是可重建索引。
- 只读副本/投影只能提供候选结果；释放前在主库复核同一 grant、冻结 manifest 和 query source，复核失败时不释放并丢弃临时结果。
- 完整事件规范化后计算 hash，短微批生成 Merkle root，并由 KMS 签名后写入独立安全域的 Object Lock/WORM 存储。
- 完整性批次、验证、归档和 legal hold 等长期控制记录各自计算 canonical record hash，通过 KMS/WORM seal 并由 `audit_event_control_record` 锚定创建事件，避免仅依赖事件三元组。
- outbox 的 `PUBLISHED` 保留到消费者重放/WORM 确认窗口结束；`DEAD` 只能经审计重放或双人 disposition 后处置，不能直接删除。
- 审计查询、解密、导出、下载、保留策略与完整性校验本身继续被审计。
- 密码、Token、Cookie、验证码、密钥、完整请求响应和文件正文永不进入审计。

## 结果

- 每次允许、拒绝和业务变化都能关联操作者、授权依据、目标、涉及用户和结果。
- 已提交业务变更的审计事件允许丢失数为 0。
- 审计写入进入关键请求路径，需要独立的容量、可用性、故障注入和恢复验证。
- 审计数据本身成为高敏感数据，需要独立 capability、脱敏、保留期和访问审计。
- 全量读取审计可能快速增长，必须按实际事件 RPS、事件大小和 subject fan-out 估算，而不能按在线人数猜测。

## 不采用的方案

- 仅记录修改操作：无法追踪敏感信息读取、搜索和导出。
- 仅保存 Nginx 或应用文本日志：缺少业务语义、涉及用户和字段差异。
- 由客户端声明操作者、结果或权限：客户端不可信。
- 同步双写远程审计服务：无法与业务事务保持原子性。
- 为每条事件维护全局单 hash 链：会形成写入争用热点。
- 记录完整 request/response：产生秘密泄漏、隐私和存储风险。
