# ADR-0005：仅账号密码登录与增量持久化

- 状态：已采用
- 日期：2026-10-29

## 背景

第一阶段实现中，管理员登录与工作区切换依赖一个由环境变量注入的固定验证码（并非真正的 TOTP），step-up 只是把会话 token 回传给客户端，实际不提高安全性，却增加了登录步骤。

同时，生产持久化在每个请求中序列化并加密整份领域状态、重写全部审计行、从数据库读取并校验整条审计链，并为每个请求写入一行 manifest；医保生命周期调度器每 2 秒也会触发同样的开销。单个检查点行采用“后写覆盖先写”，只能部署一个实例。

## 决策

1. **删除 MFA 与 step-up。** 持有正确账号和密码即可登录并进入其拥有角色对应的任一工作区；`/auth/mfa/verify` 与 `/session/step-up` 端点移除，登录结果不再返回 `MFA_REQUIRED`，所有上下文的 `assuranceLevel` 为 `AAL1`。强制改密、首次资料完善、双人复核、最后系统管理员保护等其他控制保持不变。`AUTH.MFA.*` 审计代码保留为已弃用，用于解释历史记录。
2. **密码策略**：8 至 128 个字符，且至少包含一个大写字母、一个小写字母和一个数字（ASCII）。服务端为最终裁决，各客户端使用同一规则做即时提示。服务端生成的临时密码同样满足该策略。
3. **增量持久化**：
   - 审计账本不再进入状态检查点；每个请求只追加自身新产生的审计行，并以该批次的 manifest 封存。
   - 只读操作（`@ReadOnlyState`）只写审计；其他操作仅在状态摘要变化时重写加密检查点。
   - 所有实例通过事务级 advisory lock 串行写入；每次调用先比较检查点版本与审计序号（`ledger_seq`），落后时增量加载，因此可以部署多个实例。
   - 业务拒绝（`ApiError`）与其拒绝审计一起提交；只有意外异常才回滚并从数据库重新加载。
   - 外部调用（行政区划解析、医保生命周期投递）在状态锁之外执行。
   - 过期会话、票据、幂等记录和一次性结果文件定期清理。
4. **审计哈希 v2**：覆盖事件编号、发生时间、操作者、工作区、渠道、决策、结果、请求编号、原因、涉及主体、资源、字段变化和授权证据，以规范化 JSON（键排序）计算。历史行以 `hash_version = 1` 继续按旧规则校验，链接关系不变。
5. **一次性凭据**：临时密码只存在于首次响应或一次性结果文件中；幂等重放返回 `ALREADY_DELIVERED`，结果文件在下载后立即清除，未下载的文件最长保留 24 小时。

## 结果

- 登录流程在 Web、Android、iOS 上都简化为账号密码；高权限工作区不再有第二因子。若以后需要多因素认证，应以真实的 TOTP/WebAuthn 实现并另立 ADR。
- 单个请求的持久化开销与该请求产生的数据量成正比，不再随审计账本总量增长。领域状态检查点仍是整份序列化，规模继续增长时应迁移到按表持久化。
- 早期版本的检查点中残留的明文一次性凭据在加载时被清除。
