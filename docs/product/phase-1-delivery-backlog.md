# 第一阶段实施 Backlog

- 状态：开发任务可拆分
- 日期：2026-09-18
- 当前实现说明：登录已改为仅账号密码，MFA/step-up 已移除；本文涉及 MFA/step-up 的内容为长期设计，不代表当前行为，见 [ADR-0005](../architecture/decisions/0005-password-only-login-and-incremental-persistence.md)。
- 范围：账户、基础授权、组织管辖上限、权威审计，以及已确认的“医保信息系统”统一账号/SSO 接入；不含其他业务模块和小程序

## 1. 使用规则

- 任务按 `P1-xx` 标识；依赖未完成时不绕过契约或安全边界临时实现。
- 每个任务必须同步实现、安全边界、审计行为和文档/契约。
- “后端完成”不等于阶段完成；Web、Android、iOS 都使用相同 API 语义通过验收。
- 任何范围扩张先更新 [产品基线](phase-1-account-access-baseline.md) 并评审，不把业务需求塞入底座任务。

## 3. M1：工程与契约

### P1-01 仓库工程初始化

- 建立 Maven 多模块父工程与 `gateway`、`account`、`authorization`、`organization`、`module-catalog`、`audit`、`admin`、`jobs` 模块。
- 建立 pnpm/Turborepo、Web user/admin 空应用。
- 建立 Android Gradle/Compose 与 iOS Xcode/Swift Package 空工程。
- 只提供健康检查和构建配置，不实现业务。

完成条件：本地与 CI 能分别构建服务端、两个 Web 应用、Android 和 iOS；小程序无变更。

开始前先按 [技术栈与架构基线](../architecture/technology-stack.md) 准备对应平台的构建环境。

### P1-02 契约生成与检查

- lint OpenAPI 和三个 JSON 目录。
- 生成 TypeScript、Kotlin、Swift API 模型与客户端。
- CI 检查生成物漂移、operationId 重复、稳定代码重复和 breaking change。

完成条件：三种 SDK 编译通过，客户端无手写重复 DTO/角色/capability 枚举。

### P1-03 基础环境

- Docker Compose 提供 PostgreSQL、Valkey/Redis、S3 兼容存储和本地 KMS/WORM 明确替代实现。
- 提交脱敏 `.env.example`，不提交秘密。
- 建立 OpenTelemetry request/trace 上下文和结构化日志脱敏测试。

完成条件：一条命令启动开发依赖，秘密扫描和日志禁记字段测试通过。

## 4. M2：身份闭环

### P1-04 Flyway 与数据库权限

- 按 Schema 计划实现 V001-V013。
- 建立迁移、运行时、审计追加、授权写入、dispatcher 和查询角色。
- 实现最后一个系统管理员、只追加审计和 assignment ceiling 约束。

完成条件：空库迁移、升级测试、直接越权 SQL 测试和 Testcontainers 约束测试通过。

### P1-05 初始系统管理员 Bootstrap

- 实现一次性运维命令，安全读取凭据并关闭 bootstrap secret。
- 一次性创建两个不同自然人的初始系统管理员、系统管理与系统审计显式 grant，并要求分别绑定 MFA。
- 演练双人控制、bootstrap secret 关闭和最后管理员保护。

完成条件：仓库/镜像/迁移中无默认密码；bootstrap 只能成功一次且全程审计。

### P1-06 登录、MFA 与上下文

- 实现 login、MFA verify、bootstrap、step-up 和 context switch。
- 实现 Web Cookie/CSRF 与移动 Token adapter。
- 实现 audience、授权版本和会话撤销检查。

完成条件：三工作区、五个内置角色、多角色切换和伪造 audience/workspace 安全测试通过。

### P1-07 首次改密

- 实现临时凭据、24 小时到期、`PASSWORD_CHANGE_ONLY` context 和密码历史。
- 非系统管理员创建/重置后强制改密；系统管理员按产品规则豁免。
- 改密成功撤销旧会话并签发全新会话。

完成条件：所有绕过路径和秘密泄漏测试通过。

### P1-08 Logout 与导航清理

- 服务端幂等撤销 token family。
- Web 清缓存并处理 BFCache/pageshow；Android/iOS 替换认证导航根。
- 旧 token 使用产生拒绝审计。

完成条件：Web 后退/前进/刷新、Android 返回/进程恢复、iOS 手势/Scene 恢复全部不能显示旧页面。

## 5. M3：账户与权限

- 实现影响预检、乐观锁和审计。

### P1-10 角色与管辖上限

### P1-11 账户查询与详情

### P1-23 医保信息系统 SSO 适配

- 在工作台、Web、Android、iOS 注册 `medical-insurance` 模块入口；入口只请求短时一次性服务端票据。
- Shtong 系统管理员映射 `_yb super_admin`；“医保系统管理员”映射范围受限的 `_yb admin`；`USER` 映射 `_yb student`。多角色账号按当前 workspace 解析，默认用户工作区不升权。
- `_yb` 只增加独立适配层：ticket callback、父会话 introspection/revoke、受控影子账户和 Shtong 范围投影；不改业务页面、业务逻辑、数据库业务规则和既有功能。
- 适配层在生产启用 SSO-only，拒绝旧密码登录、旧 Bearer 登录和无父会话本地会话；短时 Shtong 不可用只允许有界 grace。

完成条件：角色/范围/授权版本/退出联动和空范围拒绝行为有明确契约；两个仓库的变更可独立回滚；最终统一部署到同一服务器前完成 HTTPS、适配器密钥和反向代理配置。

这四项可以并行设计，但合并顺序必须先契约、后生成物和实现。不要从账户页面或临时登录接口绕开底座开始。
